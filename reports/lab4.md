## 问答题
### 1. 
#####  在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？
答：
(1)root inode是根目录所对应的inode，我们的easy-fs仅有一级目录，因此root node是所有文件的根目录，存储了所有文件inode的映射DirentEntry，在进行文件查询时均需要从root node开始逐级向下查询，进行文件link、unlink等操作时也需要依据root node进行操作。
(2)如果root inode中的内容损坏了，那么在进行文件查询时，无法从root node开始逐级向下查询，导致无法找到文件，从而无法打开文件、操作文件。也无法实现文件创建等文件管理。

### 2. 

##### 举出使用 pipe 的一个实际应用的例子。
>tips:
想想你平时咋使用 linux terminal 的？
如何使用 cat 和 wc 完成一个文件的行数统计？

答：
使用 cat 和 wc 命令来统计文件的行数：
```bash
cat file.txt | wc -l
```
这个命令的工作流程是：
1. cat file.txt 命令读取文件内容并输出到标准输出
2. | 管道符将 cat 命令的输出重定向到 wc 命令的输入
3. wc -l 命令接收输入并计算行数

数据的流向：
- `cat data.txt` ：从文件读取数据，输出到其标准输出
- 管道将 `cat` 的标准输出连接到 `sort` 的标准输入
- `sort` ：从标准输入读取数据，排序后输出到其标准输出
- 管道将 `sort` 的标准输出连接到 `uniq` 的标准输入
- `uniq` ：从标准输入读取数据，去重后输出到其标准输出
- `> result.txt`：将 `uniq` 的标准输出重定向到文件

管道可以连接两个进程的标准输入/输出，从而使得数据在内存中传递，不涉及磁盘I/O

### 3. 
##### 如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐，请设计一个更易用的多进程通信机制。
答：
设计一个共享内存与消息队列结合的通信机制。共享内存用于进程间的数据共享，消息队列用于进程间的同步与通信。
具体实现：
每个进程创建一个共享内存区域，用于存储进程间需要共享的数据。这部分内存被进程共享，成为数据和消息交换中心，所有进程只需与这个进程中心建立连接，即可实现进程间的数据与信息的共享。具体而言，该中心实现为一个队列，每个进程通过向队列中写入或读取数据来实现进程间的通信。
每个消息实现发送者、接受者、消息类型、优先级等信息。
```c
struct Message {
    pid_t sender;        // 发送者进程ID
    pid_t receiver;      // 接收者进程ID (0表示广播)
    uint32_t type;       // 消息类型
    uint32_t priority;   // 消息优先级
    char data[MAX_MSG_SIZE]; // 消息内容
    ...
};
```
整体架构：
```
    进程A  进程B  进程C
      \     |    /
       |    |   |
       |    |   |
     进程数据、消息交换中心
```
例如：
进程A和进程B需要进行通信，可以通过以下步骤实现：
- 消息发送 ：
    - 进程A调用 msg_send 发送消息到进程B
    - 系统将消息放入共享内存的消息队列
    - 系统通知进程B有新消息到达
- 消息接收
    - 进程B调用 msg_receive
    - 系统从消息队列中取出发给进程B的消息
    - 将消息内容复制到进程B的缓冲区
- 消息广播
    - 进程A调用 msg_broadcast
    - 系统将消息标记为广播消息
    - 所有订阅了该类型消息的进程都能接收到

这样的实现方式可以使每个进程只需要与消息中心交互，而不需要一一进行交互，大大简化了进程间的通信。此外，这样的实现方式可以支持一对一、一对多、多对多的通信方式，较为灵活、简便。
