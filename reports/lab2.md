#### 问答题
##### 1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？
答：
SV39页表项共64位，组成如下：
- [63:54]为保留位，共10位
- [53:10]为物理页号(PPN)，共44位
- [9:8]为RSW位，共两位
- [7:0]为标志位，共8位
主要标志位及其作用：
- V (Valid)：当为1时表示该页表项有效，为0时无效
- R (Readable)：控制对应虚拟页面是否可读
- W (Writable)：控制对应虚拟页面是否可写
- X (eXecutable)：控制对应虚拟页面是否可执行
- U (User)：控制在CPU处于U特权级时是否允许访问该页面
- G (Global)：表示该页在所有地址空间都有效，切换地址空间时不需要刷新TLB
- A (Accessed)：由硬件自动设置，记录自从该位被清零后对应虚拟页面是否被访问过
- D (Dirty)：由硬件自动设置，记录自从该位被清零后对应虚拟页面是否被修改过

##### 2. 缺页相关问题
1. 哪些异常可能是缺页导致的？
   答：
   在RISC-V架构中，以下三种异常可能是缺页导致的：
   - 指令页错误（Instruction page fault，Exception Code = 12）：当CPU取指令时页面不存在或无效
   - 读页错误（Load page fault，Exception Code = 13）：当CPU读内存时页面不存在或无效
   - 写页错误（Store/AMO page fault，Exception Code = 15）：当CPU向内存内写数据/执行原子内存操作（AMO）时页面不存在、无效或只读
2. 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
   答：
   当缺页异常发生时，以下寄存器会包含重要信息：
   - scause：记录异常原因和信息，其中Exception Code记录异常种类（值为12、13或15），分别对应上述三种页错误；Interrupt记录其为中断还是异常
   - stval：记录导致缺页异常的虚拟地址
   - sepc：记录发生异常的指令对应的下一条指令地址，用于异常处理后返回
   - sstatus：记录异常发生前的状态位，包括SPP段记录异常发生前的特权级
   - sscratch：是指针，指向S态上下文，例如内核栈指针
3. Lazy策略的好处
   答：
   Lazy策略的主要好处包括：
   1. 减少内存占用、提高内存利用率：只有实际使用的内存页才会被分配，避免浪费物理内存，适合那些申请大量内存但只使用其中一小部分的程序
   2. 减少无用IO操作：避免部分页面被加载进内存未被使用就释放的无用加载的IO操作，提升程序的性能
   3. 加快程序启动：不需要一次性分配所有内存，减少启动时间
   4. 支持超额分配：允许系统承诺比实际物理内存更多的虚拟内存
4. 处理10G连续内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？
   答：
   SV39使用三级页表结构，页面大小为4KB。每个页表项PTE占8字节，每个页表页包含512个页表项。
   对于10G连续内存（约2,621,440个4KB页）：
   - 一级页表（根页表）：1个页表页，占用4KB
   - 二级页表：约5个页表页（2,621,440/(512^2) ≈ 10），占用40KB
   - 三级页表：约5,120个页表页（2,621,440/512 ≈ 5,120），占用20MB
   总计**约20MB**左右的页表空间。
5. 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现
   答：
   实现Lazy策略的基本思路：
   1. mmap系统调用时，只记录虚拟内存区域的信息（起始地址、长度、权限等），不实际分配物理页面和建立页表项
   2. 维护一个数据结构（如区间树）来记录所有已mmap但尚未实际分配的虚拟内存区域
   3. 当程序访问这些区域内的地址时，会触发缺页异常，调用异常处理函数trap_handler进行处理
   4. 在缺页异常处理程序中，检查触发异常的地址是否在已记录的mmap区域内：
      - 如果在，则分配物理页面，建立页表映射，设置适当的权限，然后返回继续执行
      - 如果不在，则报错终止进程或采取其他错误处理措施
   5. 对于munmap操作，直接从记录中移除相应的虚拟内存区域，并释放已经分配的物理页面（若有）
6. Swap策略，此时页面失效如何表现在页表项(PTE)上？
   答：
   当页面被换出到磁盘时（swap out），对应的页表项中：
   - Valid位(V)设置为0，表示该页面当前不在物理内存中；其他权限位通常保持不变，以便在页面被换回内存时恢复原有权限
   - 将页面存储在磁盘上，物理页号(PPN)字段可以重新利用，用来存储该页面在磁盘上的位置信息（如扇区号或索引）
   当需要访问被换出的页面时，会触发缺页异常，操作系统根据页表项中存储的磁盘位置信息将页面从磁盘加载回内存，更新页表项，然后继续执行。

##### 3. 双页表与单页表
1. 在单页表情况下，如何更换页表？
   答：
   在单页表设计中，更换页表通常只在进程切换时进行：
   1. 保存当前进程的上下文
   2. 加载新进程的页表基地址到satp寄存器
   3. 执行SFENCE.VMA指令刷新TLB
   4. 恢复新进程的上下文并继续执行
2. 单页表下如何控制用户态无法访问内核页面
   答：
   通过页表项中的U位（User）来控制访问权限：
   对于内核页面，将对应页表项的U位设置为0。当处理器在用户态（U模式）运行时，如果尝试访问U位为0的页面，硬件会自动触发页访问异常；处理器在内核态（S模式）运行时，可以访问所有页面，无论U位是0还是1，从而确保了用户程序无法直接访问内核空间。
3. 单页表有何优势？（回答合理即可）
   答：
   单页表相比双页表有以下优势：
   1. 效率更高：用户态和内核态切换时不需要切换页表，直接切换上下文即可，避免了TLB刷新，提高了缓存命中率，并且提升了效率
   2. 实现更简单：不需要维护两套页表的一致性，降低了系统复杂度
   3. 减少了页表同步的开销：不需要在两套页表之间同步共享的映射

4. 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
   答：
   - 双页表实现下，需要在以下情况更换页表：
     1. 进程切换时：从一个进程的用户页表切换到另一个进程的用户页表
     2. 用户态和内核态之间切换时：如系统调用、中断或异常发生时，需要从用户页表切换到内核页表；处理完成返回用户态时，需要从内核页表切换回用户页表
   - 单页表实现下，只需要在进程切换时更换页表，用户态和内核态切换时不需要更换页表，因为内核和用户空间共享同一张页表，只是通过权限位控制访问。
